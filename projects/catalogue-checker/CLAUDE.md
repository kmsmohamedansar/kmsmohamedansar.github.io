# Rules for working on the Catalogue checker

Copied from the owner's portfolio plan. Follow them for every change.

1. **Plan limits.** No paid API or service. Any AI model must be free and run locally, behind a swappable setting.
2. **Data.** Public or made-up data only. Product data comes from Open Food Facts (open data, ODbL licence). Never name a retailer. Nothing from the owner's employer: no company, team, tool, customer or retailer names, no copied work code, no internal URLs, no metrics.
3. **Language.** Plain words in every README and write-up. No em dashes. Explain any jargon once.
4. **Evidence.** Keep NOTES.md dated. Save a screenshot at every milestone. Run code and show real output before claiming anything works. Record failures honestly.
5. **Numbers.** Report only numbers produced by runs in this repo. Never invent a result or a percentage.
6. **Publishing.** Don't publish or change the portfolio site until the owner says so.
7. **Story.** Chapter 1 (at work) is the owner's real experience, written generically. This build is the public practice version; say so.
8. **Finish.** End with a two-chapter case study, a claims ledger, the scored test results, and diagrams.
9. **Tests.** Checker thresholds are fixed in advance (see README) and never tuned on the answer key. Model numbers come only from real runs, never from the stand-ins used in unit tests.
