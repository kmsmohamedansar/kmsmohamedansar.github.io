# Rules for working on the Warehouse POC (Northwind Freight)

Copied from the owner's portfolio plan. Follow them for every change.

1. **Plan limits.** No paid API or service. Everything runs locally: MySQL (free, community edition) and DuckDB. Snowflake, BigQuery and Redshift are mentioned only as "the same approach applies"; no trials.
2. **Data.** Made-up data only. Northwind Freight and the warehouse vendor are fictional. No retail, grocery or CPG setting. Nothing from the owner's employer: no company, team, tool, customer or retailer names, no copied work code, no internal URLs, no metrics.
3. **No real vendor voice.** The owner plays an SE at a made-up vendor. Never write as if speaking for a real company.
4. **Language.** Plain words. No em dashes. Explain any jargon once.
5. **Evidence.** Keep NOTES.md dated. Screenshot each milestone. Run code and show real output before claiming anything works. Record failures honestly.
6. **Numbers.** Only numbers from runs in this repo, with the machine named. ROI inputs are labelled as assumptions, never as results.
7. **Publishing.** Don't change the portfolio site until the owner says so.
8. **Story.** Chapter 1 is the owner's real experience, written generically. The discovery call notes are the owner's real questions, unedited in substance.
9. **Finish.** Two-chapter case study, claims ledger, diagrams, and every document from discovery to the 90-day review linked.
